# In-game validation checklist

Generated by `python -m ae2opt export-tests`. Profile: Default (8/32/7x7x7) (normal 8, dense 32, controller size 7x7x7). Your AE2 config must match.

**Goal:** check that the game does exactly what the simulator predicts. A single mismatch means the model is wrong somewhere, and optimizer results can't be trusted until it's fixed. Note *what* differs: that tells us which rule is off.

## Setup (once)

1. Copy every `ae2opt_*.nbt` from this folder into your world's `structures` folder (`saves/<world>/structures/`; create the folder if it doesn't exist).
2. Use a creative world with plenty of open space (a superflat world is easiest).
3. Get a structure block (`/give @p minecraft:structure_block`) and set it to **Load** mode.
4. For each test, type its structure name (for example `ae2opt_t1`). Click **Load** once to show the bounding box, then again to place it. Keep tests at least 5 blocks apart.
5. Wait about 5 seconds after placing so both networks finish booting.

**What's in each positive test:**
- **The build:** main controllers, plus cable cells with input tunnels and cable anchors.
- **A shell:** dense fluix cable two blocks out, which is the tunnel network's cabling.
- **A snake of tunnel-network controllers** under the shell, with a creative energy cell under it.
- **A creative energy cell on a main controller** (main-network power).
- **Two output rigs on top:** an output tunnel feeding a dense cable with 40 ME terminals.

**How to read the results:**
- **Controller texture:** online (normal), offline (dark), or conflicted (red).
- **P2P tunnel texture:** an active ME P2P tunnel shows its lit face. Inactive ones are dark.
- **ME terminal screens:** lit means the terminal has a channel. Dark means no channel.
- **Network Tool:** right-click any cable to see that network's channels in use.

**The shell's channel count is the main pass/fail check.** Tunnels in gap cells inside a build are hidden, so you can't count them by eye. Every active tunnel uses one tunnel-network channel, so the Network Tool on the shell shows the expected number only if every tunnel is active. Counting lit tunnels on the outside is a cross-check.

Coordinates in the notes are layout coordinates (the `.json` files). In the placed structure, the corner nearest the structure block is the layout's minimum corner.

## Reporting back

For each test, fill in the **In game** column, or just list the rows that differ. Screenshots of anything unexpected help. The `.json` file next to each `.nbt` is the exact layout; `python -m ae2opt show ae2opt_t1.json` prints it layer by layer.
